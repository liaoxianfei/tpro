## 1. 总则

三者均通过 Go `ProtocolAdapter` 接入，产出同一套 `DeviceEvent` / 消费 `DeviceCommand`。容量与部署以基线万级目标为准；下表「单协议并发」仅为**单节点开发参考**，非集群上限。

| 协议 | 连接模型 | 优先级建议 | 复杂度 |
| --- | --- | --- | --- |
| HTTP | 请求/响应，可无状态 | 高（易联调） | 低 |
| 串口 / Modbus RTU | 主从轮询 | 高（工业现场） | 中 |
| Telnet | TCP 全双工文本 | 中（运维类设备） | 低 |

---

## 2. HTTP（RESTful / JSON）

### 2.1 接入要点

- 设备 HTTPS POST/GET 上报或拉取；Header 携带凭证（如 Project-Key / AccessToken）。
- 适配器侧：HTTP Server 收上报 → Decode 为 DeviceEvent；下行则 HTTP Client 调设备 URL。
- 强制 TLS1.2+；超时与幂等重试需明确。

### 2.2 陷阱

- 明文 HTTP、Token 配错、URL 拼接错误。
- 无 Keep-Alive 导致高并发下握手过多；payload 过大拖垮弱设备。

### 2.3 映射示例

- 属性上报 → `STATUS` 或 `EVENT`，`data` 为 JSON 对象（保留数值类型）。
- 平台控制 → `DeviceCommand` → POST/PUT 设备 API；响应 → `COMMAND_ACK`。

### 2.4 安全

HTTPS、鉴权头、限流与请求体大小限制；防未授权访问。

## 3. 串口（RS232 / RS485，常见 Modbus RTU）

### 3.1 接入要点

- 配置波特率、数据位、校验、停止位、流控；打开串口设备节点。
- Modbus：地址 + 功能码 + 数据 + CRC；主站轮询。
- RS485：总线两端 120Ω 终端电阻；注意半双工与地址冲突。

### 3.2 陷阱

- 接地与屏蔽不当导致误码；参数不一致；帧超时未处理。
- 轮询过密占用 CPU / 拖垮总线。

### 3.3 映射示例

- 读寄存器成功 → `STATUS`，物理量换算后写入 `data`。
- 写寄存器 → `DeviceCommand`（如 `WRITE_REGISTER`）→ 应答 `COMMAND_ACK`。

### 3.4 安全

物理隔离为主；协议层可加简单口令；网关到云侧走 TLS/VPN。

### 3.5 部署注意

串口常在**边缘网关**进程内打开；与中心 Go 集群通过边缘代理上报事件（仍转换为统一模型），避免云端直接占有现场 COM 口。

## 4. Telnet

### 4.1 接入要点

- TCP 23；登录提示交互；按提示符切分命令与回显。
- 处理 IAC 选项协商；超时判定响应结束。

### 4.2 陷阱

- 忽略协商导致乱码；提示符因厂家而异；断线未检测。
- **明文账号密码**：禁止暴露在公网，优先 SSH 或 VPN 隧道。

### 4.3 映射示例

- `show status` 类查询 → 解析键值 → `STATUS`。
- 控制类 CLI → `DeviceCommand` → 文本命令 → 解析结果为 ACK/EVENT。

### 4.4 安全

仅内网；ACL 限制源 IP；凭证加密存储；评估后尽量迁 SSH 适配器。

---

## 5. 通用转换规则（三协议共用）

- 命令 ID ↔ 协议操作（URL / 寄存器 / CLI 模板）配置化，避免写死在代码。
- 字段映射与单位换算在适配器完成；错误码映射到统一 `CommandAck.code`。
- 原始片段可进 `raw` 或 `metadata.extensions`，业务层不依赖私有格式。

## 6. 测试要点（摘要）

| 类型 | 做法 |
| --- | --- |
| 兼容性 | Mock HTTP Server、虚拟串口、本地 Telnet 服务 |
| 性能 | 并发会话与延迟分位；串口控制轮询频率 |
| 稳定 | 长稳、断线重连、指数退避（如 1s 起、封顶 60s、有限次数） |
| 安全 | HTTP 越权、Telnet 明文风险确认 |

指标示例（局域网开发态）：命令 P95 < 100ms；心跳 30s、连续 3 次超时判离线——**最终以基线万级压测结果校准**。
