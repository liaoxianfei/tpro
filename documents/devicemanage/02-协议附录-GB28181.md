## 1. 协议定位

公安/安防视频监控联网标准，基于 **SIP 信令 + RTP/RTCP 媒体**。在本平台中由 Go 侧 `GB28181Adapter` 实现，上行映射为 `DeviceEvent`，下行由 `DeviceCommand` 编码为 SIP MESSAGE / INVITE 等。

## 2. 关键特性摘要

| 特性 | 说明 |
| --- | --- |
| 消息模型 | SIP；消息体常为 XML（MANSCDP）或 SDP；媒体为 RTP/RTCP |
| 注册 | 设备向平台发起 REGISTER，Digest 认证（401 → 带 Authorization 重发） |
| 心跳 | 周期性 MESSAGE（Keepalive），典型 30～60s；平台回 200 OK |
| 控制 | 平台 MESSAGE 下发；设备 200 OK 或 MESSAGE 反馈 |
| 媒体 | INVITE 建立会话后 RTP 推流；TCP/UDP 可协商 |
| 默认端口 | SIP 5060（UDP/TCP）；RTP 端口协商 |
| 可靠性 | 依赖 SIP 重传；媒体侧注意抖动与丢包 |

## 3. 与统一模型的映射

### 3.1 上行

| 原始行为 | DeviceEvent.type | data 示例 |
| --- | --- | --- |
| REGISTER 成功 | STATUS | `{"action":"register","result":"OK"}` |
| Keepalive MESSAGE | STATUS | `{"heartbeat":true}` |
| Alarm/Notify | ALARM | 报警码、级别等（按 MANSCDP） |
| 指令执行反馈 | COMMAND_ACK | `{"commandId":"...","status":"SUCCESS"}` |

`metadata.protocol = "GB28181"`；可保留 `Call-ID`、`CSeq` 于 `extensions`。

### 3.2 下行

| DeviceCommand.command | 编码方向 |
| --- | --- |
| `play` / 预览 | SIP INVITE + SDP |
| `ptz` / 参数设置等 | SIP MESSAGE + MANSCDP XML |
| `stop` | BYE 或对应控制 XML |

事务关联：用 Call-ID + CSeq 与 COMMAND_ACK 对齐。

## 4. 接入实现要点

- Handshake：处理 REGISTER 与 Digest；会话写入 Redis（见基线 5.3）。
- 媒体：信令在接入层；RTP 建议转发至流媒体服务（SRS 等），避免在业务层解码。
- deviceId：20 位国标编码；统一 ID 空间建议前缀 `GB:` 以免与 GDJ 冲突。

## 5. 常见陷阱

1. 鉴权失败：设备 ID、域、密码、摘要算法与平台不一致。
2. Call-ID / CSeq 不唯一或乱序导致事务错乱。
3. RTP 乱序/丢包未做缓冲与校正 → 花屏、卡顿。
4. NAT 穿透与防火墙未放行 SIP/RTP 端口。
5. 厂家实现偏离标准字段，需兼容开关而非改核心模型。

## 6. 安全

- 优先 SIPS（TLS）与 SRTP（视设备支持）。
- 设备白名单 / 证书；限制 SIP 端口暴露面，防反射与伪造注册。

## 7. 测试建议

- 注册、重复注册、心跳超时下线、目录查询、实时预览、云台、报警上报。
- 与 GDJ089 同机部署时端口隔离（勿占用对方端口）。
- 抓包验证 REGISTER 握手与 INVITE/200/ACK 完整流程。
