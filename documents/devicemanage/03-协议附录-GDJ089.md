## 1. 协议定位

应急广播大喇叭 / IP 适配器场景。典型为 **TCP 短连接或长连接上的二进制报文**（含头部、业务体、CRC32），由 Go 侧 `GDJ089Adapter` 实现。

## 2. 关键特性摘要

| 特性 | 说明 |
| --- | --- |
| 传输 | TCP；可选 TLS；端口由平台约定（避免与 SIP 5060 冲突，如 6000） |
| 会话 | 报文头 SessionID 关联请求/应答；未必有独立「登录」帧 |
| 心跳 | 业务类型 0x10；间隔常 30～60s |
| 下行控制 | 如 0x01 开始播发、0x02 停止播发等 |
| 上行 | 心跳、故障、任务切换、播发结果等（0x10/0x11/0x13/0x14/0x15 等，以规范为准） |
| 完整性 | CRC32；可选签名/证书字段 |

## 3. 与统一模型的映射

### 3.1 上行

| 业务类型（示例） | DeviceEvent.type | 说明 |
| --- | --- | --- |
| 0x10 心跳 | STATUS | data 可空或带状态 |
| 0x11 查询应答 | STATUS / EVENT | 按查询内容 |
| 0x13 故障 | ALARM | 故障码入 data |
| 0x14 任务切换 | EVENT | |
| 0x15 播发结果 | EVENT / COMMAND_ACK | 与 command_id 关联时用 ACK |

`metadata.protocol = "GDJ089"`；`sessionId`、源编码等放入 metadata/extensions。

### 3.2 下行

| DeviceCommand.command（建议名） | 业务类型示例 |
| --- | --- |
| `startBroadcast` | 0x01 |
| `stopBroadcast` | 0x02 |
| 查询 / 参数设置 | 0x11 / 0x12 等 |

编码步骤概要：拼包头（如 FE FD…）→ SessionID → 业务类型与业务体 → 长度 → CRC32。实现细节以规范附录 D 为准。

设备通用应答带回相同 SessionID → 映射 `COMMAND_ACK`。

## 4. 接入实现要点

- Handshake：接受 TCP 后即可进入收发；按需 TLS。
- 粘包半包：按长度字段组帧，`Decode` 返回 NeedMore。
- deviceId：由「数据源对象编码」规范化（注意 BCD/前缀规则）；建议统一前缀 `GDJ:`。
- 与 GB28181 同集群时：**独立监听端口 + 协议路由**，禁止混解析。

## 5. 常见陷阱

1. CRC 字节序错误导致全量拒包。
2. SessionID 未递增或不匹配导致 ACK 对不上。
3. 短连接场景下下行时设备已断开 → 依赖基线离线指令 / 影子。
4. 音频实际播出路径（本地 RDS/FM/组播 RTP）与信令分离，勿假定适配器内含完整媒体栈。

## 6. 安全

- 优先 TLS；应用层签名字段按规范启用。
- 来源 IP 白名单；限制暴露端口。

## 7. 测试建议

- 心跳保活与超时下线、开始/停止播发闭环、故障上报、与 GB 设备并行互不干扰。
- 保存 `raw` 便于对照规范抓包审计。
