# 权限控制

> 文档来源：[plus-doc - 权限控制](https://plus-doc.top/#/kingtype-cloud-plus/framework/basic/permission)  
> 说明：原页面抓取超时，内容结合框架代码与 Sa-Token 用法整理。

---

## 功能概览

- 基于 **Sa-Token** 实现认证与权限校验，与「系统用户相关」中的 `LoginHelper` 配合使用
- 采用 **RBAC（基于角色的访问控制）** 模型，支持用户、角色、菜单、部门、岗位等多维度权限
- 支持 **数据权限** 控制，可按部门、本人等范围过滤数据
- 通过注解声明接口所需权限，配置简洁、扩展方便

---

## 权限校验注解

在 Controller 方法上使用以下注解即可完成权限校验（由 Sa-Token 提供，框架已集成）。

### 登录校验

```java
@SaCheckLogin
```
仅校验是否已登录，不校验角色或权限。

### 角色校验

```java
@SaCheckRole("admin")                    // 需具备 admin 角色
@SaCheckRole(value = {"admin", "user"})  // 需同时具备多个角色（AND）
```
角色标识通常与系统中「角色编码」一致，例如超级管理员角色：`TenantConstants.SUPER_ADMIN_ROLE_KEY`。

### 权限校验

```java
@SaCheckPermission("system:user:list")   // 需具备该权限
@SaCheckPermission(value = {"user:add", "user:edit"}, mode = SaMode.OR)  // 具备其一即可（OR）
```
权限字符串与菜单/按钮配置中的「权限字符」一致，如：`demo:tree:list`、`workflow:leave:add`。

### 其他注解

| 注解 | 作用 |
| --- | --- |
| `@SaCheckSafe` | 二级认证（敏感操作再次校验） |
| `@SaIgnore` | 忽略登录与权限校验，如登录接口、验证码接口 |

## 使用示例（来自本工程）

**按权限字符控制接口：**

```java
@SaCheckPermission("workflow:leave:list")
@GetMapping("/list")
public R<List<xxx>> list(...) { ... }

@SaCheckPermission("workflow:leave:add")
@PostMapping
public R<Void> add(...) { ... }

@SaCheckPermission("workflow:leave:edit")
@PutMapping
public R<Void> edit(...) { ... }

@SaCheckPermission("workflow:leave:remove")
@DeleteMapping("/{ids}")
public R<Void> remove(...) { ... }
```

**按角色控制接口（如仅超级管理员）：**

```java
@SaCheckRole(TenantConstants.SUPER_ADMIN_ROLE_KEY)
@GetMapping("/list")
public R<List<xxx>> list(...) { ... }
```

## 与登录用户配合

权限校验通过后，可在方法内使用「系统用户相关」中的 API 获取当前用户信息，例如：

```java
Long userId = LoginHelper.getUserId();
String tenantId = LoginHelper.getTenantId();
boolean isSuperAdmin = LoginHelper.isSuperAdmin();
```

根据业务需要再做数据权限或逻辑判断。

---

## 数据权限

- 除「接口是否可访问」外，框架支持 **数据权限**：按当前用户部门、本人等范围过滤查询数据。
- 数据权限范围、规则通常在系统管理（角色/菜单/数据范围）中配置，由框架在查询时自动拼接条件。
- 相关能力可参考系统模块中的 **数据权限（DataScope）** 配置与 `RemoteDataScopeService` 等 API。
